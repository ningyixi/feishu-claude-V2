# Glass material contract

Use shared `GlassMaterial.css` tokens and `glass/` helpers. Ordinary flat-canvas cards, form controls, code blocks and full-page tasks remain solid. No wallpaper is introduced to justify glass. Existing native dialog/drawer boxes, popconfirm, tooltip and toast receive CSS material over live page content. Preserve markup, dimensions, typography, border radii, business copy, focus/draft contracts and semantic colors.

`data-glass` opts an existing static surface into scene inspection. Only a readable image backdrop permits a lens. Unknown DOM, video, unsupported crops and CORS failures use theme ink and a conservative dense tint. Never claim Canvas can read arbitrary DOM. Do not apply blend mode to a slab or a subtree containing solid controls/errors; blend eligible text leaves. Direct text nodes retain normal composition to avoid markup changes. Secondary light ink is a fixed RGB 58/58/64 at .70, calibrated from the reference 60/60/67 because the latter narrowly misses 4.5:1 over white. Opacity never changes by background.

Scene sampling: 5x3 points, remove two brightest/darkest before the average, retain full sample extrema for texture. Hysteresis .45/.55, parent-and-row groups share ink, dark always light ink. Persist structural ink keys and appearance preferences only; never persist document text or image samples. Contrast uses conservative normal-composition secondary ink on every sampled point and the inner-light worst case. Raise density beyond illustrative ranges when necessary. Dense unreadable fallback tests black and white extremes. This is sampled contrast protection, not a claim to measure all screen pixels or guarantee every user-selected zero tint.

Lens: Chromium user-agent gate plus CSS.supports, decoded eight cached raster patches and neutral center, one unique invisible SVG per surface, rim-only vectors, per-channel displacement and screen merge. Move patch coordinates on resize; regenerate only when geometry/rim changes. Uniform convex round/bevel/squircle/superellipse geometry is supported. Unsupported mixed/elliptical/concave corners, unsafe compositing, animation, small or overlapping patch geometry use CSS material. Current production surfaces have no eligible image-backed static card; tests opt in an existing card over fixture imagery. Do not describe the fixture as a shipped wallpaper or current production refraction.

Global theme is `html[data-theme]`; system/light/dark and separate scales 0..1.5 are stored under `workspace.appearance.v1`. Existing Surface hosts the settings; changes apply immediately, with no unsaved settings draft. At zero, tint/highlight/saturation/brightness adjustments vanish; blur, edge and shadow remain. Reduced transparency and forced colors use solid theme/system surfaces. Preserve existing motion; transition only registered material properties.

Validation: Node material tests, compiled-preview Playwright scenarios (existing floating scenarios twice), readable image/dark/busy fixtures, resize patch reuse, independent theme preferences, compositing suppression, image-change resampling, shared-row ink, unavailable scene and preference fallbacks. Inspect screenshots. Build/deploy with OrbStack and run real HTTP stack smoke; no real model/Feishu actions in browser fixtures.
