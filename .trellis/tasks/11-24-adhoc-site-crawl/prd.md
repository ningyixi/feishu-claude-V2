# 临时需求：暴露同站点 BFS 递归抓取

## 用户诉求（2026-11-24 原话）
「为什么"临时需求"里没有广度优先算法递归解析文档啊，补上这个功能。」

## 现状事实（已读码核实）
- **算法本来就有，且不是玩具**：`src/main/java/com/lark/oapi/sample/ws/service/SiteCrawler.java` 是真 BFS —— `ArrayDeque` 队列 + `visited`/`queued` 逻辑页去重 + 同 `origin` 限制（`:810` `isSiteCrawl`/`originOf`）+ 从已抓正文里继续发现链接（`:118` `extractMdLinks`，md 与 html 链接都吃）。
- **上限处理是诚实的**：`MAX_PAGES = 200` 是**发现数**上限（`:20` 注释明确"不把前 200 页冒充完整成功"）：发现第 201 个逻辑页 → 整体容量错误（`:128-129`）。
- **调用链也在**：`SupplierKbService.add(..., boolean site)`（`:80-97`）→ `meta.site=true` → `parse`/`reparse` 走 `crawlNow(id)`（`:326-338`、`:568`）→ 落在 `<kbRoot>/<kbCode>/site-<id>/` 目录，并有取消标记（`:45`，`cancelCrawl`）。
- **缺的只是暴露**：`AdHocService.detectType`/创建与追加路径**从不传 `site=true`**，前端 `AdHoc.jsx` 也没有任何开关。历史原因清楚：`11-17-adhoc-requirement-module` 的决策 4 白纸黑字写了「siteCrawl 复选框没做」，我当时评估后没补；昨天 `11-23-adhoc-append-sources` 的「继续补充材料」也沿用了单页语义。**这是我们的缺口，不是工具能力不足。**
- 对照组：接口建档（QuickProbe）每条来源在 `docsJson` 里可带 `site` 布尔 —— 两个入口语义不一致。

## 范围
- **SC1 创建与追加都可选整站递归**：`AdHoc.jsx` 的新建表单与「📎 继续补充材料」面板各加一个勾选 **☑ URL 按同站点递归抓取（BFS，≤200 页）**，后端 `create(...)` 与 `appendSources(...)` 接受 `siteCrawl` 并**只作用于 URL 行**（本地文件/PDF/笔记不受影响）。
  - 粒度决定（我拍）：本轮**一个总开关**，不做逐行 `site:` 前缀语法 —— 多行文本框里发明私有语法更难懂、也和接口建档的 `docsJson` 结构不同。若用户以后要逐行控制，再加"每行一条来源"的结构化表单，而不是往文本里塞 DSL。**页面上要写清这条开关作用于本次提交的全部 URL 行**，别让人以为只勾了某一行。
- **SC2 抓取过程必须看得见**：条目行显示「站点抓取中：已入 N 页 / 共发现 M 页」+ 复用现成「取消抓取」按钮（`cancelCrawl`）；完成后显示总页数与产物目录。**失败页/跳过页要列出原因前 3 条**，不许静默丢页。
- **SC3 上限触发要如实**：撞 200 页发现上限时把 `SiteCrawler` 的原始错误透传到条目 `error` 与页面（"发现第 201 个页面，超出同站点 200 页上限…"），**禁止**截成"部分成功"；想抓更多只能拆成多个任务，不放宽常量（放宽需要用户明确授权）。
- **SC4 Wiki 必须等抓完才取材**：抓取期间该条目状态是 RUNNING/非 DONE，`AdHocService` 现有的"全部 DONE 才 build"门槛要覆盖站点条目，并有测试断言**站点抓取未完成时不会触发 Wiki 编译**（否则 Wiki 只吃了首屏，用户以为全量进来了）。
- **SC5 与"待新材料"提示联动**：追加站点来源后 `pendingMaterialCount` / 琥珀横幅照常生效（昨日已实现），站点条目**按整条来源计数**（不要把 200 页算成 200 条待处理材料，那是噪声）。

## 验收
- AC1 勾选整站递归 + 给一个文档站入口：KB 里出现站点条目、`meta.site=true`、`site-<id>/` 下产出多页 md，页面显示页数。
- AC2 不勾选时行为与今天完全一致（单页 URL），老任务不受影响（回归）。
- AC3 取消按钮能终止抓取，条目状态与日志如实（不是伪装 DONE）。
- AC4 构造一个超过 200 个逻辑页的本地夹具站点 → 条目 `error` 含原始容量错误、`status=FAILED`，**且没有触发 Wiki 编译**、不计入"已就绪材料"。
- AC5 站点抓取未完成时不触发 Wiki build（SC4 断言）；全部页 DONE 后才 build 且取材包含深层页面正文（用固定关键词断言，不是人眼看）。
- AC6 同一 URL 行重复追加不因站点目录重复入库（沿用 `source` 去重语义）。
- AC7 全量 `mvn test` 红数不超过基线 **`430 跑 / 3 失败 / 1 错误 / 1 跳过`**（4 条为既有 Windows 伪脚本与 temp 环境红）；前端 `node --test`（19 pass）与 `npx playwright test`（零环境变量，当前 31 passed/4 failed，4 条为既有移动视口与缺 Firefox）不得新增失败。

## 明确不做
不放宽 `MAX_PAGES`；不做跨站点/外链抓取；不做 JS 渲染（抓不到 SPA 页面就如实报告失败原因，**不许**用"抓到了 N 页"掩盖）；不改 `SiteCrawler` 的 BFS 与去重逻辑；不改接口建档（QuickProbe）来源结构；不引入新依赖（不装爬虫框架）。

## 验证方式
站点抓取需要网络目标：**用本地 HttpServer 夹具**（`127.0.0.1` 随机端口）搭一个多层文档站（含 md/html 链接、一个 201 页的超限站、一个会卡住的慢页），全部在测试内完成。**禁止**在测试里访问任何真实供应商域名。现网端到端（真文档站）由主会话部署后与用户一起验。
