# 临时需求：知识库可删除单个文档

## 用户诉求（2026-11-24 原话）
「"临时需求"现在的供应商知识库现在还是没有"×"来删除一个文档吗？补充这个功能。」

## 现状事实（已读码核实）
- 后端能力**现成**：`SupplierKbController.java:109` `DELETE /api/supplier-kb/entries/{id}` → `SupplierKbService.delete(id)`（`:360`）。
- 工作台 `KbPanel` **本来就有删除**：`Supplier.jsx:966`「删除知识库条目」带二次确认。
- **是我把它关了**：`AdHoc.jsx:386` 传 `readOnly`，而 `Supplier.jsx:901` 注释写明"readOnly=true 时隐藏补充表单与**全部写操作**"。昨天开「继续补充材料」面板时没有回头拆这个开关。
- **连带坑**：`SupplierKbService.delete:362-366` 会写一条 `SupplierKbRemoved` 墓碑（记录 kbCode+type+source）。删除后再追加同一来源的行为**未被任何测试定义**，很可能"加不回来"或"加回来但不明原因"，而"删错了想恢复"正是用户的日常操作。

## 范围
- **KD1 把 `readOnly` 拆成细粒度权限**：`KbPanel({ canAdd, canDelete, canReparse, canStage })`。
  - **默认值必须让工作台行为逐字不变**（工作台现有调用零改动即等价）；接口建档/快速建档的结果卡**保持全只读**（谁在用 `readOnly` 必须先 grep 清楚，逐个确认，不许顺手放开）。
  - 临时需求传：`canDelete=true`、`canReparse=true`、`canAdd=false`（它已有专用追加面板，含笔记双框；**不要**出现两套添加入口）。
- **KD2 删除确认要说清后果**，复用现成 `confirmAction`：站点条目用 `dialog`（影响可达 200 页），普通条目用 `popconfirm`。文案必须包含：删掉的产物（md / 站点 `site-<id>/` 目录）、以及**"当前 Wiki 版本仍含该内容，需重编译才生效"** —— 不能让用户以为删了就立刻从知识里消失。
- **KD3 删除必须触发 Wiki 重编译**：复用 `11-23-adhoc-append-sources` 的 `forceWikiRebuild` 通道；琥珀横幅与 `pendingMaterialCount` 语义升级为**区分"新增"与"移除"**（删除不能被算成"新增材料"，也不能删完就没有任何待处理提示）。
- **KD4 墓碑交互必须有明确结论并有测试**：删除后追加同一来源 → 采用**允许重新入库 + 清除墓碑 + 页面提示「已恢复该来源」**（推荐）；若实现中发现语义冲突，宁可给可读拒绝（"该来源此前被删除，如需恢复请点这里"），**严禁**出现"点了没反应/条目凭空消失/静默不入库"。
- **KD5 材料清空时的状态要可读**：删到 0 条来源时不得进入无意义状态：保留旧 Wiki 版本、提示「材料已全部移除，此时重编译将得到空 Wiki，建议先补充材料」，并且「重试本段」不被禁死。

## 验收
- AC1 临时需求知识库里每条文档都有「×」；点击出确认，确认后条目与产物文件消失，列表与统计实时更新。
- AC2 站点条目删除：确认框是 dialog 且文案含页数影响；删除后 `site-<id>/` 目录不残留。
- AC3 删除后琥珀横幅显示"移除待重编译"语义（不是"新增 N 条"），Wiki 重编译完成后新 Wiki **不再包含**被删文档的固定关键词（关键词断言，不靠人眼）。
- AC4 删除后重新追加同一来源 → 按 KD4 的结论走，且有测试钉住（不允许静默失败）。
- AC5 删到 0 条来源：任务与页面状态可读，「重试本段」可用，无死锁。
- AC6 **工作台与接口建档结果卡零回归**：`KbPanel` 调用点在未显式传新 props 时行为与今天逐字一致（含隐藏写操作的旧语义），有测试证明；grep 出全部 `readOnly` 使用处并逐个列在回报里。
- AC7 全量 `mvn test` 红数不超过基线 **`447 / 3 失败 / 1 错误 / 1 跳过`**；`node --test`（19 pass）与 `npx playwright test`（零环境变量，当前 34 passed / 4 failed）不得新增失败。

## 明确不做
不做多选/批量删除；不做回收站或"撤销删除"UI（墓碑机制按 KD4 处理，但不新增恢复界面）；不改 `SiteCrawler`/抓取逻辑；不改 Wiki 编译管线；不动 `Eval*`、`CardBuilder`、Flowable。

## 排序
独立一棒（改动集中在 `Supplier.jsx` 的 `KbPanel`、`AdHoc.jsx`、必要时的 `AdHocService`/`SupplierKbService`）。完成后主会话自验 → 提交 → 打包 → 脱离会话重启。
