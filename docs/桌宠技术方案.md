# 桌宠技术方案 — OpenPet 调研与 feishu-claude-V2 集成设计

> 2026-09 · 参考项目：[OpenPet](https://github.com/X-T-E-R/OpenPet)（`Z:\YIXI\work\OpenPet`，v0.1.6，GPL-3.0-or-later）
> 本文 = 桌宠需求的开发总纲：OpenPet 技术方案拆解 + 与本系统的集成设计 + **开发路由速查表**（不会的地方按表去 OpenPet 源码学）。

---

## 1. 需求与结论先行

**需求**：给飞书机器人管理系统加"桌宠"——桌面上有一只透明置顶的宠物，用动画和气泡实时表达系统的工作状态（实例在思考/跑工具、数字员工在干活/需要支持、E2E 流水线阶段流转/成败）。

**结论**：**直接运行 OpenPet 独立应用 + Java 后端经它的本地 HTTP API 推状态事件**。零改动对方代码、1~2 天可出 demo、GPL 许可证安全（进程间 HTTP 通信不构成衍生作品）。自定义形象按它的资产规范出图即可。若未来要"每个数字员工一只宠物"或"持续状态动画"，再走 fork 路线（§6.3）。

**为什么 OpenPet 天生合适**：它的定位就是"agent 工作状态显示器"——内置 6 种 Companion 事件（`thinking / tool-running / reviewing / success / failure / attention`），与本系统的实例状态机、数字员工生命周期、E2E 流水线阶段几乎一一对应（映射表见 §5.2）。

## 2. OpenPet 技术栈与架构

```
┌────────────────────────────────────────────────────────────┐
│ 外部控制方（AI Agent / CLI / MCP / ★本系统 Java 后端★）        │
└──────────────┬─────────────────────────────────────────────┘
               │ HTTP（默认 127.0.0.1:17321，仅 loopback，无鉴权）
┌──────────────▼─────────────────────────────────────────────┐
│ Rust 壳（Tauri 2.11）                                        │
│  ├─ http_api.rs  手写 TcpListener HTTP 服务（CORS *）        │
│  ├─ lib.rs       AppState / 16个 tauri command / 系统托盘 /  │
│  │               宠物导入(本地+网站,防SSRF) / TOML 设置持久化  │
│  └─ 事件总线：emit_to("pet", "pet-action"/"pet-say"/…)        │
└──────────────┬─────────────────────────────────────────────┘
               │ Tauri IPC (invoke / emit / listen)
┌──────────────▼─────────────────────────────────────────────┐
│ React 19 渲染层（Vite 8 + TS，无路由库：?window=pet|settings） │
│  ├─ PetWindow.tsx  动画/气泡/拖拽/右键菜单/行走/点击穿透       │
│  └─ src/pet/  animation.ts(状态机) motion.ts(运动)            │
│               PetSprite.tsx(渲染) catalog/events/settings.ts │
└──────────────┬─────────────────────────────────────────────┘
               │ CSS background-image + background-position 逐帧
┌──────────────▼─────────────────────────────────────────────┐
│ 资产层：pets/<id>/ = pet.json + spritesheet.webp              │
│ （1536×1872 atlas，8列×9行，单格 192×208，每行一个动画）        │
└────────────────────────────────────────────────────────────┘
```

关键选型：**Tauri 而非 Electron**（产物 5~15MB 级、内存小）；渲染**不用 canvas**，纯 CSS background-position + rAF 时钟 + 纯函数帧求值（`getPetFrameAtTime`），因此渲染层零平台依赖、可直接进浏览器跑（它自己的 Playwright e2e 就是浏览器模式）。

## 3. 核心技术点拆解（学习重点）

### 3.1 透明置顶无边框窗口（Windows）

`src-tauri/tauri.conf.json` pet 窗口五件套：`decorations:false`（去边框）+ `transparent:true`（WebView2 透明合成）+ `alwaysOnTop:true`（HWND_TOPMOST）+ `skipTaskbar:true`（不占任务栏）+ **`shadow:false`（关键细节：不关阴影会在透明区外画一圈矩形投影）**。配合 CSS `html/body/#root` 全透明。

### 3.2 点击穿透（全项目最精巧的部分）

宠物窗口是 320×N 矩形，但只有精灵区域该响应鼠标。方案 = **窗口级 `setIgnoreCursorEvents` + 80ms 全局光标命中轮询**：因为窗口常态穿透时 DOM 收不到 mousemove，所以每 80ms 主动读全局光标坐标（`cursorPosition()`）→ 换算窗口逻辑坐标 → 判断是否落在精灵矩形（+4px padding）或右键菜单内 → 动态切换穿透开关。CSS 侧第二道保险：`.pet-window{pointer-events:none}` + `.pet-hit-target{pointer-events:auto}`。拖拽期间强制不穿透。→ 源码：`src/PetWindow.tsx` 的 `syncCursorHitTarget`。

### 3.3 动画系统

- **9 个动画 = 精灵图 9 行**（行序约定硬编码在 `src/pet/animation.ts` 的 `PET_ANIMATIONS`，所有宠物共享）：第0行 idle / 1 running-right / 2 running-left / 3 waving / 4 jumping / 5 failed / 6 waiting / 7 running(原地) / 8 review
- **每帧独立时长**（如 idle = 280,110,110,140,140,320ms，末帧加长做停顿）；rAF 只当时钟，帧号 = 时间的纯函数 → 掉帧不乱节奏
- 三层行为仲裁（都在 PetWindow）：①动作播放（`playAction` → `actionActiveUntilRef` 时间戳内抑制其他动画，播完回 idle）②行走循环（120ms tick，动作优先）③闲置自娱（45s 无交互后每 30s 随机播一个动作）

### 3.4 运动系统

**不是随机漫步，是"地面巡逻"**：y 恒定贴工作区底部（地面），x 恒速左右移动，撞工作区边缘（含 8px 边距）掉头并切 running-left/right。每 4s 重读 `currentMonitor().workArea`（物理像素÷scaleFactor）→ 不会走进任务栏、多显示器/分辨率变化自适应。窗口移动由**前端** `setPosition(LogicalPosition)` 驱动，Rust 无自主移动逻辑。拖拽后 y 可停在任意高度，恢复行走保持高度横移。→ 源码：`src/pet/motion.ts`（纯函数，可单测）+ PetWindow 移动循环。

### 3.5 交互链路

- **点击**：DOM onClick → 随机/固定动作池选动画 → 本地播放（不经 Rust）；拖拽后 `suppressClickRef` 防误触
- **拖拽**：pointerdown + 4px 阈值 → 优先原生 `startDragging()`（Win32 SC_MOVE 最顺滑）→ 失败回退手动 delta+setPosition
- **右键菜单**：前端自绘 div（非原生），弹出前先播一次 review 动画；菜单矩形参与点击穿透命中测试
- **托盘**：Rust `TrayIconBuilder`，四项菜单（设置/显示/隐藏/退出），随语言设置重建
- **悬停**：双通道（DOM mouseenter + 80ms 轮询），效果 = 上浮 3px + 放大 1.03 + 投影；`hoverPause` 默认暂停行走

### 3.6 HTTP API（对外驱动核心，`src-tauri/src/http_api.rs`）

裸 `std::net::TcpListener` 独立线程，手工解析请求（body ≤64KB，3s 超时，`Connection: close`，全路由 CORS `*`）。监听地址**只允许 loopback 或 0.0.0.0**，默认 `127.0.0.1:17321`（可用环境变量 `CODEX_PET_RUNTIME_HOST/PORT` 或设置页改，重启生效）。**无鉴权**（设计上靠 loopback 隔离——这是安全边界，别轻易改 0.0.0.0）。

| 端点 | 请求 | 作用 |
|---|---|---|
| `GET /api/status` | — | RuntimeSnapshot 全量状态（含 recentEvents 最近12条，可对账） |
| `POST /api/action` | `{"animationId":"waving\|jumping\|waiting\|running\|review\|failed"}` | 播放动作 |
| `POST /api/say` | `{"text":"...","ttlMs":4000}` | 气泡（512 字符截断，TTL≥500ms） |
| `POST /api/event` | `{"type":"thinking\|tool-running\|reviewing\|success\|failure\|attention","message":"...","ttlMs":4000}` | **Companion 事件 = 动作+气泡一次驱动**（主力端点） |
| `POST /api/import/local` | `{"source":"dir\|pet.json\|.webp"}` | 导入本地宠物包并激活 |
| `POST /api/import/website` | `{"url":"https://petdex..."}` | 网站导入（仅 HTTPS，防 SSRF：拒私网/环回，重定向后二次校验） |
| `GET /api/pets/<id>/spritesheet` | — | 精灵图二进制 |

事件 → 动画映射（Rust `emit_companion_event` 与前端 `src/pet/events.ts` 一致）：thinking→waiting、tool-running→running、reviewing→review、success→jumping、failure→failed、attention→waving；受设置 `eventReactions/eventBubbles` 开关控制，气泡文本优先用 message。

### 3.7 宠物资产规范（自定义形象必读）

- 包 = `pet.json`（仅 4 必填字段：id/displayName/description/spritesheetPath）+ `spritesheet.webp`
- 精灵图硬契约：WebP 带 alpha、≤12MB、**1536×1872、8列×9行、单格 192×208、行序按 §3.3 固定**（帧时长归 animation.ts 管，pet.json 里没有帧信息）；未用格子留透明
- id 规则：2–72 位小写字母数字连字符；`nia` 保留，冲突自动加 `imported-` 前缀
- 制作/校验流程有现成 Claude skill：`skills/openpet-asset/SKILL.md`（可直接喂给你的数字员工出图）
- 现成宠物可从 Petdex / Codex Pets / SpriteYard 导入（注意素材版权）

### 3.8 设置与持久化

单一数据源在 Rust（`AppState`），TOML 落盘 `%APPDATA%\dev.xter.openpet\data\settings.toml` + `runtime-config.toml`；写入前服务端硬钳制（scale 0.5–2.0、TTL 500–60000、步速 1–32 等）；前端零持久化，全靠 RuntimeSnapshot 同步。

### 3.9 构建与分发

`pnpm install && pnpm tauri:dev` 开发；`pnpm release:bundle` 出包。Windows 产物 = NSIS .exe + .msi，依赖 WebView2 Runtime（Win10 2004+ 基本预装）。可直接用 GitHub Releases 现成安装包。

## 4. 许可证与安全红线

- **GPL-3.0-or-later**：✅ 安全做法 = OpenPet 作为**独立进程**运行、本系统经 HTTP 调用（进程间通信不构成衍生作品）；⚠️ 红线 = **把它的源码（含 animation.ts/PetSprite.tsx 等"看起来很干净"的前端文件）拷进本仓库** → 衍生作品，分发时整包 GPL。想借鉴渲染思路就**自己重写**（CSS background-position + rAF 是通用技术，60 行的事）+ 自绘资产
- 它的 API 无鉴权，靠 loopback 隔离——**不要**为了省事把监听改 0.0.0.0（等于把"任意人可操控桌面+读状态"暴露内网）
- 导入第三方宠物素材注意版权

## 5. 与 feishu-claude-V2 的集成设计

### 5.1 架构（当前拓扑：全部同机）

本系统 Spring Boot、用户桌面、（未来的）OpenPet **都在同一台无影云电脑上** → Java 直接 POST `127.0.0.1:17321`，**连桥接进程都不需要**：

```
Spring Boot ──PetNotifyService（新增，虚拟线程+safe-fail）──► OpenPet HTTP API ──► 桌宠动画/气泡
     ▲                                                            │
     └── 状态源：InstanceStatusService / EmployeeService / E2EOrchestrator
```

**PetNotifyService 设计**（新增 `service/PetNotifyService.java`）：
- 配置：`application.yml` → `pet.openpet.enabled`（默认 false，装了 OpenPet 再开）+ `pet.openpet.base-url`（默认 `http://127.0.0.1:17321`）
- 核心方法 `notify(String type, String message)`：虚拟线程 POST `/api/event`，**2s 超时、失败静默**（safe failure 哲学——OpenPet 没启动绝不能影响业务，日志 debug 级）
- 防抖：同 type+message 5 秒内去重；`WORKING` 类持续态每 5s 重发一次（OpenPet 事件是**瞬时脉冲**，动画播一遍就回 idle——持续工作要周期重发才能"一直在跑"）
- 启动探活：`GET /api/status` 一次，不通就标记 disabled 并每 5 分钟重试探活（别每条消息都撞墙）

**接线点（三处，全是现成钩子）**：
1. `InstanceStatusService.resolveAll()`：状态**变化**时推（它有现成的趣味状态机）
2. `EmployeeService`：`startDemand`（开工）、`markDone`/`markFailed`、STUCK/SUPPORT 上报处各加一行 `petNotify.notify(...)`（或直接挂在 `postMessage` 里——所有员工上报自动同步给桌宠，一处接线全覆盖 ★推荐）
3. `E2EOrchestrator`：`setStage` / `finish` / `fail` / `broadcastAsk` 各一行

### 5.2 状态映射表（业务状态 → Companion 事件）

| 业务状态 | event type | 气泡文案示例 |
|---|---|---|
| 实例 THINKING（思考中） | `thinking` | 「渠道1」思考中… |
| 实例 WORKING/TOOL_RUNNING | `tool-running` | 「渠道1」执行工具: Bash |
| 实例 GENERATING（奋笔疾书） | `thinking` | 「渠道1」正在输出… |
| 实例 DONE（任务完成） | `success` | 「渠道1」任务完成 ✓ |
| 实例 CRASHED / DISCONNECTED | `failure` | 「渠道1」信号中断，自动重连中 |
| 实例 IDLE/FISHING/SLEEPING | （不推，避免噪音） | — |
| 员工需求开工 | `thinking` | 👔 小王开工：《对接XX接口》 |
| 员工需求完成 (REPORT) | `success` | 👔 小王完成：《对接XX接口》 |
| 员工需求失败 / 重启中断 | `failure` | 👔 小王的需求失败了，去面板看看 |
| 员工卡住 (STUCK) / 需要支持 (SUPPORT) | `attention` | 👔 小王需要你的支持：缺测试账号 |
| E2E DESIGNING（设计用例） | `reviewing` | 🧪 测试设计师独立设计中 |
| E2E EXECUTING / FIXING | `tool-running` | 🧪 E2E 第2轮执行 5 条用例 |
| E2E ask 暂停（等你回答） | `attention` | ⏸ E2E 群聊有提问等你回答 |
| E2E 全部通过 | `success` | ✅ E2E 全部通过 (8/8) |
| E2E 失败终止 | `failure` | ❌ E2E 流水线终止 |

### 5.3 单宠物策略（v1）

OpenPet 是**单宠物单例**（窗口 label="pet" 固定）——一只宠物代表整个系统，用气泡文案区分是谁在动（上表已含实例名/员工名前缀）。"每个数字员工一只宠物"当前做不到，见 §6.3 演进。

### 5.4 落地步骤

1. **PoC（10 分钟）**：装 OpenPet（Releases 安装包或 `pnpm install && pnpm tauri:dev`）→ `curl http://127.0.0.1:17321/api/status` 探活 → curl POST `/api/event` 三种类型看动画
2. **PetNotifyService**（半天）：按 §5.1 实现 + 配置开关
3. **接线**（半天）：三处钩子各加一行；员工通道推荐直接挂 `postMessage` 一处全覆盖
4. **体验调优**：持续态重发间隔、防抖窗口、把 `autonomousWalking` 关掉（静止时事件表现最清晰）、气泡样式（settings 里有 soft/comic/glass/terminal 四种）
5. **自定义形象（可选）**：按 §3.7 规范出一套"数字员工"主题精灵图（可用 openpet-asset skill 喂给实例生成），`POST /api/import/local` 导入

### 5.5 未来拓扑变化（应用迁 ECS 后）

若采纳"应用迁 ECS 7×24 常驻"方案，OpenPet 仍在你的桌面机 → Java 不能直连 loopback。两个选择：
- **桌面 sidecar 桥**（~100 行）：SSE/WebSocket 订阅 ECS 上的状态流 → 转发 `127.0.0.1:17321/api/event`（Spring Boot 侧加一个状态订阅端点即可）
- 或 fork OpenPet 让它自己长连（§6.3）

## 6. 演进路线（需要更多能力时）

### 6.1 持续状态动画（小改 fork）
事件脉冲 → 持续态：给 PetWindow 的 `actionActiveUntilRef` 机制加一个"持续事件"类型（带 `until` 时间戳），改动集中且小。

### 6.2 新事件语义（小改 fork）
6 类事件是封闭枚举（未知 type 直接 400）。要加"部署中"之类：Rust `CompanionEventType` 枚举 + `emit_companion_event` 映射 + `src/pet/events.ts` + （若新动画）animation.ts 行定义 + 重画精灵图行——四处联动，量级可控。

### 6.3 每员工一只宠物（中改 fork）
宠物窗口是单例。多宠物 = 动态创建多窗口（Tauri `WebviewWindowBuilder`，label 参数化）+ AppState 按宠物 id 分片 + HTTP API 加 petId 维度。改动集中在 lib.rs 窗口管理与 http_api.rs 路由，渲染层可复用。**fork 分发注意 GPL 义务**（对外分发安装包必须开源衍生品；纯内部使用不分发则无碍）。
