# 供应商知识与开发上下文

## 使用流程

1. 在供应商工作台选择供应商，补充接口文档、PDF、本地 Markdown、商务私聊或笔记。URL/PDF 入库后点解析；聊天和笔记直接保存为文本。
2. 为材料选择使用阶段：通用、文档分析、接口实测、代码开发或仅留档。通用材料每次交付；仅留档不自动注入。默认通用保持旧数据行为。
3. 在工作流模板中给节点指定上下文阶段。旧模板默认按标题识别；新模板建议显式选择，避免依赖标题。未知阶段节点会交付所有非留档材料。
4. 执行文档分析和实测节点。后端会读取所选材料正文；未解析、空白、文件不可读或超过预算会阻止派发。上游工件缺失也会报错。
5. 实测使用绑定实例已配置的 Postman MCP。工作台观察 `runCollection` / `sendRequest` / `executeCollection` 工具事件，保留输入和返回。只有成功工具事件同时包含方法、URL 和带状态码、body/stream 的 HTTP 返回结构才计入证据。官方 runCollection 默认只返回测试摘要，因此执行规范已附带逐请求 Tests 脚本，用 pm.request / pm.response 生成 SUPPLIER_EVIDENCE 结构化测试记录；工作台识别这些真实工具返回。工具列表、空返回、普通通过摘要、纯文字“测过了”不计入证据。缺少证据不能完成实测节点。
6. 确认节点完成，报告和实测证据自动进入同一供应商知识库。人工修改报告也会回存，并保留节点已有实测证据。
7. 写代码准备中保存会议文档、配置、公司 spec 和提示词生成 Skill。对接 Skill 在工作基本信息中配置。路径必须是运行本服务主机可读的绝对路径；Skill 可以指向目录或 SKILL.md。规范链接需先在该供应商库中解析。
8. 点击“用公司 Skill 生成提示词”。后端先校验上述材料和已完成的实测证据，读取公司 Skill/spec 正文。在类库路径所属的 Trellis 项目下创建 `.trellis/tasks/supplier-<工作ID>`、PRD、任务元数据和上下文快照，再通过绑定实例调用模型生成提示词。模型输出后，程序再次附带原始上下文和任务路径，避免生成过程省略重要材料。生成结果入库为“仅留档”，避免反复注入自身。工作台记录生成依据的指纹；开发节点执行或完成前会重新核对，材料更新后必须重新生成。
9. 把最终提示词发送给开发实例，在指定 Trellis 任务内推进。已有 PRD 不会被生成过程覆盖。上下文快照按 SHA-256 保存，旧快照保留，implement/check 引用切换到当前快照。

## 交付记录

每个节点展示本次请求的 SHA-256、准备时间、字符数和服务器端完整请求快照位置。快照在供应商知识库目录的 `.deliveries/` 下。知识库正文按条目 ID 和 SHA-256 标记，便于核对使用的版本。

卡点答复会重新读取知识库与规范。上下文预算：所选知识正文 120000 字符，Skill/spec 60000 字符，完整开发提示词 240000 字符。超限会明确报错，需调整材料阶段或拆分任务；不会静默截断上游工件。

## 运行要求与边界

- Postman MCP 必须配置在绑定实例的 Claude CLI 中。只配置工作台本身不等于实例已有插件。插件不可用时应输出卡点，配置后重试。
- 证据来自 CLI 实际工具事件，不是根据模型报告推断。它证明观察到了带请求/返回的工具执行，不代表所有接口都已覆盖、业务结果成功，或可以替代人工核对目标环境。
- “文本进入模型请求”和“模型理解并遵循所有规则”是不同的保证。程序负责材料选择、正文交付、前置检查和实测推进门禁；生成的代码仍需按公司 spec 测试与评审。
- Skill 内引用的额外文件仍由执行实例读取；缺失时要求卡点。工作台读取的是配置入口的正文，不会递归执行 Skill 中的任意脚本。
- 工作台只写入目标项目自己的 Trellis 目录；如果类库路径找不到 `.trellis/workflow.md`，生成会失败并提示初始化。
- 前后端构建与测试可在 OrbStack 中执行，镜像分别使用 `maven:3.9-eclipse-temurin-21`、`node:22-alpine`。
